# Mac cloud sync and autofill — 2026-10-10

Development integration slice; full production synchronization/autofill tasks remain open.

## Cloud sync

File → Cloud Sync provides a native provider-folder picker, one local binding per vault plus an authenticated provider declaration shared by its revisions, explicit Sync Now/Disconnect, and enrollment of an existing original-identity cloud vault on another Mac. Choose a dedicated folder managed by iCloud Drive or Google Drive for Desktop; direct Google OAuth and mobile provider adapters are not implemented by this folder route. The provider label is user-selected; a local fixture folder is not evidence of a real cloud transfer.

PWDTWO retains content-addressed encrypted KDBX revisions instead of overwriting a shared head. Parent references are inside authenticated encryption. Incoming files must match their ciphertext hash, decrypt with the vault component, have the expected owner, and form a complete acyclic ancestry graph. Locked downloads are quarantined without replacing active data; unlock authenticates them before reconciliation. Missing previously staged provider files stop reconciliation; they are never automatically recreated. Changing the declared provider requires the still-outstanding migration protocol. Local edits remain usable offline. The native timer rotates connected vaults every minute; it does not reset the inactivity timer.

One descendant branch can be adopted; concurrent branches with identical vault-level settings use a common authenticated base and a native combined-record review. Independent entry edits merge; simultaneous changes to one record keep both as separate records, and edit/deletion retains the edited record. Every encrypted source revision remains available. No clock determines a winner. Different vault settings/generator history, independent roots, changed encryption keys or missing ancestry stop reconciliation. Those cases still need complete conflict/rotation UX.

Provider-folder reconciliation does not acknowledge remote cloud delivery. NSFileCoordinator coordinates local File Provider access, not remote compare-and-swap. This candidate retains up to 256 revisions/128 MiB per folder/staging set and never automatically compacts them. Retained sync revisions are separate from the single user backup. Capacity/retention, provider retirement/deletion/migration, scheduled backup handover and real two-device provider evidence remain production gates.

## Browser and native app autofill

File → Set Up Autofill offers native setup controls. Chrome uses an activeTab-only MV3 toolbar action, no HTML vault popup, and a separately signed native host. The app verifies the host's signed process and same-user socket peer; the host checks its Chrome parent and fixed allowed extension origin. The host verifies the app before sending captured login data. Bounded little-endian frames, one native selection, exact HTTPS origin, request/document IDs, monotonic expiry, replay refusal and app-session generation constrain credential release. Browser scripting targets the same document and rechecks URL/fields; ambiguous forms, iframes, non-default HTTPS ports and cross-origin form actions fail closed. Submission is manual.

The browser context menu captures a supported login only after a deliberate action, then offers native review into the ordinary editor. It does not automatically save. Multi-page login, approved-host aliases/mismatch approval, inline generation, automatic save/update recognition, configurable auto-submit and advanced card/passkey/OTP filling remain open. PWDTWO currently must be running; automatic app launch from an extension remains open.

Xcode automatically provisioned the shared App Group and system AutoFill credential-provider capability with the existing team. Authorized Safari web-extension and AuthenticationServices credential-provider bundles are packaged in integration-profile builds. Safari uses the same native chooser; compatible apps use OS-supplied service identifiers and return ASPasswordCredential only after selection. No unattended credential release or arbitrary-app coverage is claimed. Enable the extensions in Safari/System Settings; current/previous browser/OS ceremonies and sandboxed IPC need actual installed validation.
