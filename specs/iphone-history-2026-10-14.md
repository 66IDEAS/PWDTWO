# iPhone entry-history preview and restoration

PWDTWO iPhone 0.4.2 (8) adds the native iPhone history slice of T025/T055/T084 and UX35. Open an entry's **View previous versions** link to see a dated list, newest first. Selecting a version opens a read-only native preview with changed-field indicators, the source vault, and individually masked/revealable/copyable sensitive values. Card numbers show their last four digits while masked. Disabling masking displays sensitive values directly, without misleading reveal controls. Reveals reset on leaving the preview, masking changes, background transitions or invalidated authorization.

The preview covers the complete editable snapshot: kind, title, username/cardholder, password, website, notes, card details, folder, tags, favorite, custom fields and attachments. Empty values and removed field/file sets are visible so users can see what a restore will remove from the current entry. Historical attachments are listed by name and size; their complete bytes participate in restoration. Attachment opening/export remain separate mobile features. Copy buttons use the device's optional clipboard expiry policy; stale preview copies are refused. OS text-selection Copy menus retain their existing OS behavior.

**Restore This Version** requires confirmation that the complete entry, custom fields and historical attachments will become current. Restoration keeps the entry/vault identity and Trash state, retains all existing history, and appends the version that was current immediately before restoring. It sets a new modification timestamp and uses the same encrypted atomic/CAS publication, Data Protection, AutoFill-copy retirement and automatic foreground sync queue as a saved edit. It does not remove unresolved cloud conflicts. New retained-version timestamps use the previous modification time where available, with retention-time fallback for older records without one, matching the Mac's existing behavior.

The controller binds a preview to its originating application session, unlock generation, exact current entry and selected revision. Changes, lock/reunlock, another controller, unknown versions and replay invalidate it. Restoration refuses active editors, a retained protected draft in the target vault, trashed entries and unchanged snapshots. Trash entries may be previewed; the user must restore the item from Trash separately. An external local publication is additionally protected by the existing encrypted-file CAS even if the visible model has not yet refreshed. Saving can fail after publication/durability uncertainty; the UI does not promise that every failed confirmation rolled back the file.

## Validation

The combined iOS 26.2 simulator run passed 21 checks: seven new history, eight existing session and six AutoFill. Cases verify every restored field/custom field/attachment, retention and restart, restoration back to the retained current version, stale and repeated requests, lock/reunlock and foreign-session rejection, protected drafts, Trash, unknown/no-op versions, external encrypted publication refusal, automatic publication without manual Sync and concurrent-peer conflict preservation/convergence. All fixtures are isolated fictional vaults/folders; no user vault, password or cloud account is involved.

One initial conflict test incorrectly required an unannotated restored title after keep-all reconciliation. The existing merge may label either branch “(conflict copy)” depending on branch order. The final test explicitly verifies that permitted title annotation and every other restored field/file exactly, along with retained history and peer convergence. No merge behavior was changed.

After the combined run, only the preview's mask-control rendering changed; controller/test sources remained identical. A final complete restoration/restart case and both device/simulator compilation verify the resulting source. [Build/check evidence and fingerprints](../dev/iphone/results/2026-10-14/history/summary.json).

Both native products include the existing AutoFill extension. Physical installation still awaits its Apple App Group profile association for both targets; the existing physical app remains unchanged. Physical UI/VoiceOver acceptance and iOS27 runtime remain open. Explicit history clearing and advanced mobile attachment workflows remain separate tasks; no automatic history expiration is introduced.
